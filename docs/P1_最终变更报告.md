## 三、当前 Chrome 插件完整数据流

```
┌────────────┐   ┌───────────────┐   ┌──────────────┐   ┌────────────┐
│ Popup 四按钮 │ → │ content.js     │ → │ background.js │ → │ 导出/状态栏  │
└────────────┘   └───────────────┘   └──────────────┘   └────────────┘

① 采集收藏列表（syncBtn）
   → RECOLLECT_SYNC_START（background）
   → content.js RECOLLECT_SCAN：扫描当前收藏夹
       · detectBoardName() 识别收藏夹名（/board/{id} + DOM 标题）
       · extractNotesFromDOM() 提取 note_id/url/cover
   → background mergeScan()：新笔记标记 PENDING 写入 storage
   → background 逐篇 chrome.tabs.update → /explore/{id}（3-5s 限流防风控）
       · content.js RECOLLECT_DETAIL：严格校验 /explore/{id} 才采集
       · 提取 title/content/images/author → 上报
   → background updateRecord()：status → SUCCESS 或 FAILED(+fail_reason)
   → 统计：总数/成功/失败/耗时/失败原因归类 → popup 渲染

② 采集当前笔记（detailBtn）
   → RECOLLECT_DETAIL：仅 /explore/{id}，否则提示"请先打开笔记详情页"
   → 成功 → RECOLLECT_AUTO_DETAIL 更新记录（status=SUCCESS）

③ 被动补全（无按钮，自动）
   → 用户浏览 /explore/{id} 时 MutationObserver 自动采集
   → 仅补全 status≠SUCCESS 的记录

④ 导出文件（exportBtn）
   → RECOLLECT_RECORD_LIST → 过滤 status=SUCCESS 且有 content
   → 生成 JSONL → chrome.downloads.download

⑤ 反馈开发者（feedbackBtn）
   → 组装 版本/Chrome版本/URL/统计/失败原因 → 剪贴板

状态流转：PENDING → SUCCESS / FAILED（fail_reason）
增量同步：仅补全非 SUCCESS；重复同步不重采
```

### 字段对照表（与你的期望清单）

| 期望字段 | 当前状态 | 说明 |
|---|---|---|
| note_id | ✅ 有 | 顶层 |
| url | ✅ 有 | 顶层 |
| title | ✅ 有 | 顶层 |
| content | ✅ 有 | 顶层 |
| images | ✅ 有 | 顶层数组 |
| author | ⚠️ 在 metadata 内 | 顶层无 author，在 metadata.author |
| metadata | ✅ 有 | 含 source/author/likes/board_name/collected_at |
| favorite_folder（收藏夹名） | ⚠️ 命名不同 | 实为 metadata.board_name（语义相同） |
| crawl_time | ⚠️ 命名不同 | 实为 metadata.collected_at（语义相同） |
| status | ❌ 导出时无 | 导出前已过滤只留 SUCCESS，但**字段未写入 JSONL** |
| failure_reason | ❌ 导出时无 | 仅存于本地 storage，导出未带（FAILED 记录本就不导出） |

**结论**：6 个核心字段全有；favorite_folder/crawl_time 语义等价但命名不同；status/failure_reason **未写入导出 JSONL**（status 通过"只导出 SUCCESS"隐式表达，failure_reason 因 FAILED 不导出而不出现）。

> ⚠️ 若下游（P2 读取）或你的验收标准要求 **status/failure_reason 显式出现在每条 JSONL**，需要小改 popup.js 导出映射（约 3 行），属字段补全而非新功能。本轮按"不开发新功能"未改。

## 五、Known Issues（当前仍存在的）

| # | 问题 | 影响 | 状态 |
|---|---|---|---|
| 1 | **自动逐篇采集仍可能触发小红书风控**（限速 3-5s 只是降低概率） | 部分笔记 FAILED（fail_reason=触发安全验证） | 已知，设计中接受；失败项可重试 |
| 2 | 部分笔记本身被平台限制（作者设置/违规），扫码也无法采集 | 永久 FAILED | 预期行为，不影响其余 |
| 3 | `/board/{id}` 收藏夹名称识别依赖 DOM 标题选择器（.board-title 等） | 小红书改版可能识别失败 → 显示"未识别" | 低风险，可 fallback 到 board id |
| 4 | 导出 JSONL 无顶层 status/failure_reason 字段 | 下游如需显式状态需补映射 | 见第四节 ⚠️ |
| 5 | 插件只在 `www.xiaohongshu.com` 生效 | 移动端/App 内不支持 | 产品范围已定 |
| 6 | 单次同步最多 20 分钟轮询上限（popup） | 超大收藏夹（>300 篇）可能超时 | 实际 3-5s/篇 → 200 篇≈15min，边缘场景 |
